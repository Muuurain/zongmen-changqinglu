# v1.2.3 Android APK 适配交接

## 更新概要

本次将现有 Electron 网页游戏增加 Capacitor Android 外壳，完成手机窄屏布局、触控、前后台、返回键和本地存档桥接，并新增 Android APK 的构建脚本与发布流程。项目版本从 1.2.2 更新到 1.2.3；Android `versionCode` 为 10203，应用 ID 为 `com.zongmen.changqinglu`，最低支持 API 24，使用 API 36 编译。

## 改动范围

- `package.json` / `package-lock.json`：版本递增并加入 Capacitor Android/App/Filesystem 依赖及 Android 构建命令。
- `capacitor.config.json`、`android/`：新增 Capacitor 原生工程、Manifest 配置、API 版本、版本信息、软键盘 `adjustResize` 及可选发布签名配置。安装图标和启动图使用项目已有 `build/app_icon.png`，未加入新绘制素材。
- `android/gradle.properties`：启用 AGP 的中文/非 ASCII Windows 路径检查覆盖项，以支持当前仓库目录名。
- `android/app/build.gradle` / `android/build.gradle`：固定使用已安装的 Build Tools 36.0.0，避免 AGP 在受限网络中自动下载其他 Build Tools 版本。
- `scripts/build-android-web.js`：将网页源码组装到 `www/`，把原生桥接入口注入页面并用 esbuild 打包插件；`scripts/build-android-apk.js`：统一执行网页构建、Capacitor 同步、Gradle APK 构建、APK 复制，支持 debug、release 和安装到设备。
- `scripts/android-maven-mirror.init.gradle`：仅当 Maven Central 在特定网络下 TLS 失败时，可通过环境变量作为 Gradle 初始化脚本临时启用 Google 托管的 Maven Central 镜像；默认仍使用标准 Maven Central 配置。
- `scripts/android-native.js`：使用 Capacitor Filesystem 将四个存档槽写入应用私有文件；首次启动时迁移旧 localStorage 存档；将生命周期与 Android 返回键转为页面事件。
- `index.html` / `css/style.css`：增加移动 viewport 与 safe-area 支持；窄屏切换为顶部信息栏、横向滚动导航、单列卡片、可滚动表格/弹窗、触控尺寸与横屏压缩布局。
- `js/game.js` / `js/ui.js`：Android 端读档从原生桥接读取、存档写入私有文件；保存按钮、返回开始界面和退出前等待磁盘 flush；后台自动保存并暂停音乐，恢复前台时按之前状态尝试续播；系统返回键按页面和弹窗状态逐级处理。
- `.gitignore`：忽略 `www/`、Android/Gradle 构建产物、本机 SDK 配置与签名密钥配置。签名 keystore 不随代码库发布。
- `release-android/`：本次构建生成的 APK 放在该目录，属于本次交付产物。

## 接入和运行方式

运行 `npm ci` 后设置 JDK 21 与 `ANDROID_SDK_ROOT`，再执行 `npm run android:apk` 构建 debug 包，或准备 `android/keystore.properties` 后执行 `npm run android:release-apk` 构建签名发布包。APK 会复制到 `release-android/`。详细环境组件、签名、验收与故障处理见 [Android_APK_打包发布指南.md](Android_APK_打包发布指南.md)。

所有网页改动继续维护在 `index.html`、`css/`、`js/`、`assets/`。`www/` 与 `android/app/src/main/assets/public/` 是构建生成内容，重新运行脚本时会覆盖，不应直接修改。

## 本机签名注意事项

本次 release 签名使用仓库外密钥库 `D:\Android\zongmen-release.p12`，别名为 `zongmen-release`；密码只在当前机器的忽略文件 `android/keystore.properties` 中。该密钥库和属性文件不在 Git 交付内容中。后续发布人员需从本机安全备份取得相同 keystore 与密码；若更换密钥，既有用户将无法直接覆盖安装升级。不得提交任何密钥或密码。

本次出包不涉及 GitHub 上传、安装包商店发布或自动更新；APK 需由后续发布负责人自行验收和分发。

## 后续版本操作提醒

发布新版本时，先提升 `package.json` 与 `android/app/build.gradle` 的 `versionName`/`versionCode`；脚本会自动采用 `package.json` 版本命名 APK。在相同签名密钥下构建。复测竖屏和横屏、触屏导航、返回键、前后台音乐、首次旧存档迁移以及新存档重启恢复。升级测试前先备份本地存档与密钥。
