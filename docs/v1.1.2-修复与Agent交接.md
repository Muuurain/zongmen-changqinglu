### 整体运行模型

这是无后端的原生 JavaScript 单机经营游戏。页面依次载入 data.js、game.js、ui.js；UI.init 读取自动档或创建新局，然后绑定按钮并渲染。玩家点击闭关一月才推进时间。UI 调用 Game 执行规则，data.js 提供参数；Electron 只承载窗口，不向页面开放 Node。

## 月度结算与状态约定

### 闭关一月的执行顺序

nextMonth 先拒绝覆灭、未选事件、未处置战果和进行中的雷劫，再按以下顺序结算：建筑产出和停产计数 → 弟子修炼 → 通商收益 → 伤势、年龄、寿元、忠诚及继位 → NPC 世界演进 → 附庸与商队 → 客卿、联盟、派系 → 分宗与世界事件 → 历练归来 → 普通事件 → 月份跨年 → 覆灭判定 → 建立待选事件队列 → 自动保存。

月度事件在产出与时间推进后供玩家选择，选择不会再推进月份。队列顺序为派系、世界、历练归来、普通事件、本月要事。必须成功完成一个选项才移除队首；资源不足保留原事件。覆灭后仅保留通知，不能靠尚未处理的招募事件复活。

### 人员互斥规则

stationary 表示存活、未历练、未护送、未渡劫且未为他人渡劫护法；atHome 再排除分宗驻守；available 再排除受伤。派岗、战争、护送、历练、建立分宗统一使用 available，避免一个弟子同时承担互斥任务。

普通突破和雷劫使用 ritualAvailable，允许弟子在本宗或分宗就地进行。canGuard 要求护法健康、阶位足够、与突破者同处本宗或分宗，且不能护法自身。生产岗位可兼修，护送与历练期间停止日常修炼；分宗驻守继续修炼。

### 新增或强化的存档字段

| 字段 | 用途与恢复方式 |
| --- | --- |
| saveVersion = 2 | 保存时写入结构版本；旧档按缺省值补齐并校验。 |
| pendingEvents[] | 保存事件类型、配置快照、历练弟子 ID 或通知列表；启动和读档后恢复队首。 |
| sect.lastWarMonth | 使用 year-month 键；同目标宣战、总攻胜败均占本月次数。 |
| sect.lastLectureMonth | 每个目标每月最多一次讲学。 |
| alliance.lastCouncilMonth | 成功议事后写入；支付失败不占次数。 |
| spiritSect.lastTradeMonth | 每个灵界目标每月最多一次跨界贸易。 |
| disciple.tribulation | 保存已过波次 wave、已用丹药 pills 和 guardians；每一雷后自动保存。 |
| caravan.cost、sect.lastTactic | 前者用于返还采购本金；后者供围点打援的俘虏加成使用。 |
| danfangHaltMonths | 修缮丹炉选项真正令下一次月结丹房停产。 |

存档仍使用 localStorage 的 zm_cql_save_0 至 zm_cql_save_3：0 为自动档，1—3 为手动档。浏览器与 Electron 的存储环境独立；本轮测试使用独立上下文，未读取或覆盖玩家实际存档。

## 养成与人员生命周期修复

### F01  普通弟子不增长修为

原 monthly cultivation 仅让宗主和演武场弟子正常修炼，空闲普通弟子被遗漏。新增 cultivationGain 与 addExp，由 nextMonth 遍历全部存活弟子。空闲正常修炼，生产岗位半速兼修，演武场专修获得其等级加成；UI 详情直接展示实际每月增量。

### F02  修炼与生产的状态不一致

原外出、重伤和岗位状态缺乏统一限制。健康且可用者才能派岗或出战；重伤不生产、不修炼，历练与护送暂停日常修炼。演武场加成限定给该岗位弟子，异心产出折扣落实到建筑计算。岗位转移先校验目标，避免失败时丢掉原岗位。

### F03  突破丹药和护法按钮失效

showBreakthrough 的 render 闭包读取局部 pills，而按钮修改 _btState.pills，导致画面与确认参数分离。渲染统一读取 _btState，护法列表也统一来源；确认后清除弹窗操作状态，重复调用不能重复扣药。丹药必须为合法整数且不超库存，护法去重并校验位置、健康和境界。

### F04  经验溢出和绕过雷劫

日常修炼、传承、历练、议事与全界事件统一通过 addExp 限制到当前小阶上限，满修为等待手动突破。canBreakthrough 拒绝大乘圆满普通突破，避免直接进入渡劫境绕过九雷；旧档中仍存活的 realm=8 人物恢复为大乘圆满满经验，等待正常渡劫。

### F05  分宗弟子成长被阻断

驻守分宗不应等于正在赶路。区分可派遣人员与可就地修行人员，分宗弟子正常修炼、突破及渡劫，护法须同处一界。派岗、护送、历练和出战仍不能使用分宗驻守者，避免跨界重复投入。

### F06  死亡和离宗后的掌门及岗位异常

原突破陨落、历练事件陨落、客卿离宗、飞升等路径各自改 alive，继位和清理不一致。集中到 removeDisciple：清岗位、历练和渡劫状态，按需要留传承，掌门离开立即继位，无人存活立即覆灭。继任者优先选在宗高阶者，必要时召回外派者并释放其护送。

### F07  初始寿元和客卿俸禄错误

makeDisciple 过去分别随机年龄与剩余寿元，两者不对应；现在只抽一次年龄并据此算寿元。客卿年龄上限低于境界寿限，避免新招即寿尽。俸禄改用空值回退，配置中的 0 不再误变成 10；高阶超出表长时界面也按实际的 10 灵石回退显示。

## 战争与外交收益修复

### F08  同月反复攻击刷钱

原宣战小战与编队总攻都没有共享月度记录。新增 monthKey、warError 和 lastWarMonth，两入口使用同一校验，真正交战即记录本月；胜负都消耗次数，跨年不混淆。无效编队或无人可战不会占次数，存档重载保留限制。

### F09  非法目标与重复战后处置

warError 拒绝覆灭宗门、附庸以及待处置目标。postWar 在修改 broken 前先验证三种合法选择，结算后立即清除待处置状态，再次调用不能领奖。UI 总攻和处置后自动保存；重启或再次推进月份会恢复战后处置窗口。

### F10  编队重复算人和战术显示不更新

编队校验前中后排、每排容量、弟子存在与可用性及全阵去重；calcAssaultPower 也去重，避免同人多排叠加战力。战术渲染读取 _warState.tactic，按钮选择会改变高亮与说明。实际截图暴露前中后链接因空白换行占满弹窗，已改为同行按钮，恢复底部总攻按钮的可见性。

### F11  覆灭宗门复活与旧关系残留

worldTick 跳过覆灭和待处置目标，不再把覆灭势力的 power 从 0 回填到最低 50；通商收益和事件关系效果排除覆灭势力。宣战时取消同盟、贸易，并从联盟成员中移除；联盟讨伐也只累计有效盟友，避免向已征服或已敌对势力借战力。

### F12  围点打援描述与结算不一致

原战术文案称能获得更多俘虏，后续处置并未读取所选战术。总攻记录 lastTactic，灭门俘虏判定使用围点打援的 1.5 倍倍率，同时遵守弟子容量。没有改动其原有胜率和战损参数。

### F13  外交操作无限领取或重复扣费

讲学改为每个宗门每月一次，要求健康可用的传道职业弟子；联盟议事每月成功一次，支付失败可重试。通商、结盟已达成时，在支付前拒绝重复操作；战争状态下不能继续签贸易或同盟。正向外交关系收益实际应用外交长老加成，日志同步显示实际变化值。

### 明确采用的规则

本次选择“每目标每月一次”，不同目标之间独立计数。旧档缺少 lastWarMonth 时，允许迁移后的首次交战；之后按新规则执行。此限制约束同一存档的正常操作，不引入联网校验，也不阻止玩家主动读取更早的手动档回到历史状态。

## 经营与事件流程修复

### F14  商队成功仍丢失采购本金

原派出扣除灵石货款，成功归来只加“利润”，未返本金；界面又误用宗门商品库存限制数量。明确为花灵石采购后贩运，成功返本金加净利润，失败损失货款，不扣本地灵药或矿石。记录 cost，兼容旧商队按单价乘数量推算。保留原路线、风险与利润公式。

### F15  派遣参数和人员重复使用

商队数量限定正整数，拒绝负数、小数与错误路线货物组合；护送者必须可用且无岗位。历练也要求可用且先卸任。建立分宗验证唯一 ID、健康、境界、非掌门和最少人数，防止重复一个弟子凑人数。分宗伤者不参与分宗产出战力。

### F16  灵界贸易同月无限获利

spiritDiplo 先要求分宗存在，再按灵界目标记录 lastTradeMonth。每目标每月只能成功贸易一次，失败不改变资源和次数；月份变化后恢复资格。相关默认字段随旧档补齐，原收益数值未调整。

### F17  资源不足导致事件窗口和队列丢失

原 toast 会替换正在选择的弹窗，队列又先出队，失败后选项无法重试。现在 _drainQueue 仅查看队首，成功后 completePendingEvent 才出队与保存。toast 在现有窗口内追加文本提示，保留按钮和选择状态。普通、世界、历练与派系选择均补合法索引校验和防重复入口。

### F18  历练资源结果触发未定义函数

applyAdvOption 的资源展示调用了不存在的方法，付费历练选项会在扣资源后异常。增加 Game.resourceText 统一展示，补齐每个历练事件的全部选项测试，并以固定随机值覆盖概率成功和失败；经验奖励也纳入统一上限。

### F19  声明有效但未真正应用的配置

升级建筑时计入 HERITAGE.sources.buildingLv；丹炉修缮效果写入 haltDanfang 并设置 danfangHaltMonths，下次月结实际停产。战争与负面事件分别接入 war、order 长老加成；保留既有生产和修炼加成。普通事件收留伤者遵守弟子居容量，关系类随机效果在无有效宗门时安全退出。

### F20  宗门覆灭后被待选事件复活

全员寿尽时不再生成可选择事件，只保留本月要事。若最后一人在世界事件中陨落，completePendingEvent 会清除后续非通知项目；招募与招募客卿也拒绝已覆灭状态。测试覆盖月结寿尽和事件中死亡两条路径。

## 存档与雷劫恢复修复

### F21  读档异常和旧档缺字段

load 先解析到临时对象并校验，再替换当前状态。检查日期、资源非负、境界/职业/灵根、唯一弟子 ID、建筑级别、势力、事件和雷劫结构；损坏 JSON 或关键字段错误时返回 false，保留当前进度。save 和 saveInfo 捕获存储或解析异常，UI 不再把失败显示为成功。

### F22  非法岗位与重复掌门残留

旧档补 jobs、caravans、pendingEvents、generation 等默认值，重算 nextId 并限制经验。清理未建建筑、错误岗位列表、死人、外派者、重复 ID 和超员岗位；多掌门保留一个，无掌门且有人存活则自动推定继任者。覆灭势力清除贸易、同盟和战后状态。

### F23  自动保存吞掉尚未选择的事件

原事件队列仅存 UI 内存，月结自动保存后关闭游戏会丢选择。pendingEvents 保存事件配置快照及弟子 ID，UI.init、doLoad 与月度错误分支均能恢复。支付失败不出队；成功后清理对应 UI 指针再保存，双击或旧回调不能再次结算收益。

### F24  渡劫可跳雷或关窗重置

dujieWave 要求第一雷开始，之后仅允许已过波次加一；首次校验与扣除丹药，保存准备项，之后使用已保存的 pills 和 guardians，不能临时改药或换人。每一雷后保存；关窗、重开和读档从下一雷继续；渡劫和护法不能被重复派遣，未完成雷劫不能推进月份。

### F25  雷格误判和终局重复执行

旧初始结果数组的真假判断使未发生的雷格错误标为失败。界面只将数值 1 与 -1 视为已通过或失败，恢复时按已过波次填充。终局清除渡劫状态，失败按配置施加惩罚，飞升通过统一移除与继位流程，再给传承奖励；完成后再次点击不再重结算。

### F26  弹窗样式与确认回调残留

modal 每次替换内容时清掉事件专属样式，避免上一种事件背景污染下一窗口；确认回调执行前清空，减少重复操作。doSave、doLoad 给出真实结果，读档成功后重新渲染并续接队列。普通突破、总攻和事件选择在成功接受操作后清理临时状态。

### 迁移与恢复的边界

未修改 localStorage 的键名，也未直接迁移玩家机器上的实际存档。缺省字段可补齐，明显损坏的关键数据被拒绝；这不是任意损坏存档的修复器。旧版本未保存的“未选事件”与“已过雷数”无法凭空恢复，新版产生并保存的流程可以恢复。

改代码时应同时检查 state 中的流程字段和 UI 中的临时指针。不要再次把业务流程仅放进弹窗闭包，也不要在资源验证之前出队或扣费。

## 验证结果与实际操作记录

### 自动逻辑验证

命令：npm test；等价为 node --test scripts/game.test.js。使用 Node 内置 node:test、assert、vm 与内存 localStorage，不增加项目依赖。最终 92 项通过，失败、跳过均为 0：30 项场景测试、49 项普通/世界/议事选项测试、13 项历练选项测试。

连续模拟采用固定随机种子，运行 180 个月并每年保存再读取，验证年份到太元 16 年 1 月、资源有限且非负、经验不超阶上限、存活掌门恰一名、事件能正常处理。其他定向检查覆盖战争跨年与读档限制、胜败计次、返本及遇劫、无效参数、重复点击、满容量、覆灭和雷劫九波。

### 实际界面验证

scripts/ui-smoke.js 通过 Playwright 驱动已安装的 Microsoft Edge。遍历 10 个导航页面；实际点击闭关、丹药加减、护法和战术；验证重复宣战不改钱、资源不足后仍可选免费项、事件重启恢复、战后处置恢复、第一雷后重启继续第二雷，共 9 组关键交互。未发现页面脚本异常或非音频资源加载失败。

检查了突破、战争、事件错误提示与雷劫恢复截图；战争编队排版经截图发现问题后修正并重跑。未做人工音频听感验收，也未对所有随机种子、显示器组合和数值平衡作穷尽验证。上述通过结果针对本轮已实现的检查范围。
