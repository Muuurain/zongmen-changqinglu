## 3. 弟子状态与生平模型

### 状态约定

人物始终保留在 `state.disciples` 中，不通过删除数组项来移除人员。`alive` 保留为旧代码的“仍参与宗门运行”标志，不用于区分具体离宗原因。

| `status` | 展示状态 | `alive` | 行为 |
| --- | --- | --- | --- |
| `active` | 在宗 | `true` | 继续参与原有修炼、岗位、战斗等系统 |
| `deceased` | 陨落 | `false` | 寿尽、突破/渡劫失败、秘境死亡或战损陨落；保留生平 |
| `expelled` | 逐出山门 | `false` | 活着离宗；不触发死亡传承，不再参与宗门事务 |
| `departed` | 离宗 | `false` | 忠诚过低叛逃、欠薪客卿离去等 |
| `ascended` | 飞升 | `false` | 正常飞升，沿用已有飞升收益 |
| `unknown` | 离册（旧档原因未记载） | `false` | 旧存档仅记载 `alive=false`、无法确认是死亡还是离去 |

新增字段：

- `biography`：时间线数组，项为 `{date, age, realm, stage, kind, text}`。记录入门/创宗、突破成败、宗门战争、强敌战损、历练出发/归来/事件、客卿身份、长老受封、分宗派驻、继位、接受传承及离宗结果等关键经历。不逐月刷入重复修炼记录，不受宗门志 300 条截断限制。
- `exitReason`：明确的陨落或离宗原因。
- `exitTime`：`{year, month}`，用于显示日期及按实际年月排序档案。
- `finalPower`：离宗前战力快照。详情不再用当前宗门长老加成重新计算旧人物战力。

主要接口：

- `recordDisciple(d, kind, text)`：追加生平。
- `discipleStatus(d)`：统一状态显示。
- `removeDisciple(d, legacy, status, reason)`：统一退出当前宗门运行，保留原人物资料与生平。
- `resolveCombatCasualty(d, injuredMonths, reason)`：判定新增的强敌战损结果。
- `expelDisciple(id)`：校验并执行逐出，返回 `{ok, disciple, saved}` 或 `{err}`。

离宗时统一清除岗位、长老/掌门身份、分宗驻守及分宗名册、护送引用、渡劫/历练进度、其他渡劫者的护法引用和自动突破开关。身份转为非在宗后，不再月度修炼、生产、战斗、领取客卿俸禄或贡献宗门加成。掌门真实陨落仍自动继位；继任者从分宗召回时同步清理分宗名册。

## 4. 强敌陨落规则

`COMBAT_FATALITY_CHANCE = 0.05` 位于 `js/game.js` 顶部。**这是对已经被选为战损对象的弟子的条件概率，不是每个月、每名弟子的死亡概率。** 随机值 `< 0.05` 时陨落，否则按原配置重伤；已离宗人物不会重复结算或重复发放传承。

| 场景 | 新规则 |
| --- | --- |
| 外交宣战的小队交战 | 战败时，原本选中的重伤者有 5% 概率陨落 |
| 攻打山门 | 战败，或守方战力高于攻方时，原战损名单逐人判定 5%；占优获胜仍为原来的重伤 |
| 普通秘境争夺 | 不敌他宗修士时判定 |
| 历练采药遭妖蟒、救人遭魔修、对抗妖狼 | 对应原本失败/不敌分支判定 |
| 兽潮、魔道联军、天魔来袭 | 原战损对象判定；宗门防御战只从在本宗且未被其他活动占用的人物中取战损对象 |
| 联盟讨伐 | 战败战损对象判定；战力和战损人员只取健康、在本宗且可出战的弟子，避免外出者无故阵亡 |

商队遇劫、假丹、心魔、主动逃跑等原有一般伤势事件没有额外增加死亡判定。原有突破失败表、九霄雷劫失败表、年轻弟子深入上古秘境的 **20% 陨落**等既有规则保留，本次补齐其真实原因与留档状态。

相关选项/战争准备界面补充风险说明，战报明确区分重伤名单与陨落名单。若攻城获胜但全宗已经陨落，则不再进入战后招降/合并流程；`postWar` 同样拒绝覆灭宗门处理战果，避免靠招降“复活”。

## 5. 逐出山门与查看入口

入口：**弟子 → 详情 → 逐出山门 → 确认**。确认文案说明身份/岗位/供奉终止、生平保留与不可撤销。

规则：

1. 不可逐出掌门或已离宗人物。
2. 历练、商队护送、渡劫或为他人护法期间不可逐出。
3. 该弟子有待处理的历练事件时，需先完成事件，避免悬空的待选事件。
4. 可以逐出重伤、任职、任长老或驻守分宗的非掌门弟子；引用会统一清理。
5. 不发死亡传承、战利品或返还招募费；状态为 `expelled`，无召回/复活/重新入宗入口。
6. 执行后立即尝试保存到自动档；若写入失败，结果弹窗提醒手动保存。

弟子页新增 **人物留档** 区域。所有已陨落、逐出、离宗和飞升人物都可查看姓名、状态、最后境界、年龄、离宗原因与生平详情。离宗详情为只读，头像不播放修炼光环，不展示可继续修炼或逐出操作；死亡人物显示寿元已终止。

## 6. 开始界面与自定义开局

启动时不再自动载入游戏或直接创建新局。首先显示开始页：

- **继续上次修行**：从自动档进入；没有自动档且没有当前周目时禁用。
- **开创新宗门**：显示初代宗主姓名、性别（男/女）和宗门名表单。已有周目/自动档时先确认覆盖自动档，表单未成功提交前保留当前周目与原自动档。
- **读取存档**：保留 0 自动档及 1～3 手动档入口，成功后进入游戏并恢复待处理事件、战果和雷劫。

`Game.newGame({name, gender, sectName})` 先验证字段，再替换 `state`。名称去除首尾空格后为 1～20 个字符，允许 Unicode 字母/数字及间隔点、空格、下划线、连字符，拒绝 HTML/控制字符；性别为明确枚举。默认仍为顾长风、男、青云观，初始境界/职业/资源平衡沿用原设定。选择女性后使用对应现有女性头像，无需新增立绘。

顶部新增 **主菜单**。返回菜单会尝试自动保存；本次运行中点“继续本次修行”直接恢复内存中的周目，避免因重读较早存档丢失进度。保存失败会提示，当前内存进度仍保留。
