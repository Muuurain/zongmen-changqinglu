### 1.2 黑边、黑闪的归因与边界

1. **已观察到素材残留**：突破中的暗色人形/底块、闪光灰黑晕边、雷云青黑硬块，在不同底色合成时暴露。RGBA 不等于真正去底干净。
2. **已观察到帧格污染**：修炼和突破主体未可靠落在等宽格内，叠加 rem 与原图像素错配，会出现硬条、断边、相邻帧残片。
3. **需要接入时继续检查的切换问题**：未解码就换图、换图时清空容器、末帧越界、弹窗反复重建。此次没有证明所有切换黑闪均由同一原因造成，不能只去一次黑底就宣布解决。
4. 场景中正常的暗山、夜空不是黑边；“图片最外圈没有不透明黑点”也不能替代“每帧内部无底板”的检查。

### 1.3 纯显示逻辑改进，不应交给美术重画

- 原图切帧、帧号、渲染尺寸、位移和背景缩放使用同一比例；修复后在四种窗口尺寸重测。
- 修炼特效与真实头像分层；按钮、数值、称谓与头像中部设为保护区。
- 图片预加载并解码后替换，保留固定占位；快速切换时只提交最后一次请求的资源，避免错图、空黑块和旧图闪回。
- 卡图和头图配置焦点；现有好图优先调整构图/容器，不因错误裁切全量重画。
- 主背景、面板纸纹与深色遮罩多重叠加造成灰雾感，应调整合成；不是背景图分辨率不足的直接证据。
- 建议弹窗淡入/微位移 160–220ms、按钮反馈 100–140ms，仅对需要的变换、透明度、颜色做过渡；减少动态效果时使用静态代表帧或取消装饰。以上是后续实现建议，本次未修改样式。

## 4. 统一目录、风格与制作合同

### 4.1 文件位置

沿用现有 `assets/anim/`、`assets/avatar/`、`assets/icon/`、`assets/ill/`、`assets/portrait/`、`assets/ui/`；保留现有根目录背景位置。新文件名使用 ASCII、小写与下划线，不加入日期、中文或空格。

- 动画仍在 `assets/anim/`；重做的 5 个已使用动画与可选 sparkle 保留旧文件名。**新网格与旧代码不兼容，必须待播放器适配后才覆盖运行资源。** 制作过程中使用项目外暂存目录，验收后一次接入，不提前覆盖旧文件。
- 产业图标转入已有 `assets/icon/`，使用 `icon_building_<产业id>.png`；新边框/分隔线转入已有 `assets/ui/`。旧文件在全引用确认移除前保留，防止存量路径失效。
- 根目录旧头像不要求本轮迁移。以后如统一到 `assets/avatar/`，应显式更新 `avatarPath` 的前两张映射，不能只移动文件。
- 不建立平行的 `images/`、`effects/`、`new_assets/` 运行目录；不把设计预览、棋盘格、参考图、联系表、源工程放入运行时资源目录。
- 图片 PNG 使用 sRGB；特效/图标/边框用 RGBA，完整插画与头像用 RGB。PNG 为本轮基准，不因浏览器可能支持其他格式而擅自引入 GIF、视频或额外动画库。

### 4.2 美术方向与构图

延续现有国风水墨与细线设色：青绿、墨色、玉白为基础，金色用于突破/灵力，朱红用于警示和战斗。效果克制，禁止赛博霓虹、现代 UI 面板、照片拼贴、Q 版、拟真 3D 塑料材质及重度眩光。复用的旧图只作为风格参照，不把整张旧图底色烘入特效。

静态场景统一建议 1536×864（16:9）PNG，交付可以从更高分辨率母版等比缩小。主要叙事物放在横向 20%–80%、纵向 32%–68% 的中心安全区；顶部/底部为可裁环境。当前 3:1 左右的宽图槽只保留这条中部区域，必须提供裁切预览，不能以“原图很完整”替代实装验收。大人物肖像不要出现在场景边缘；一张事件插画只表达一个主题，不绘制按钮、数值或文字。若未来容器改回 16:9，可使用完整画面。

### 4.3 动画统一技术合同

1. 交付**逐帧 PNG 原文件**及按下表合成的 **PNG 精灵图**。运行时使用表中目标路径；源帧与工程文件在制作交付包中，验收后不必进入游戏 assets。AI 不能可靠直接排版时，先生成逐帧，再用工具严格合成，禁止接受“看起来像序列帧”的长画。
2. 同一动画的帧尺寸、镜头、中心/落点固定；无随机缩放、镜头抖动、亮度漂移、主体漂移。网格按从左到右、从上到下（row-major）编号，0 起始；所有格有效，不附标签、间隔或外框。
3. 真 RGBA，straight/unassociated alpha，不能预乘到黑/白底后直接存回。半透明边缘须有正确色彩，透明像素附近做颜色扩散以防采样黑晕；透明背景不能是画出来的黑色、白色或棋盘格。
4. 每格外沿至少 4px 全透明，发光软边必须在安全边界内衰减；切帧时不得采到邻格。不得把一个画面跨多个格。角色、头像、人形剪影、黑色底板不得混进通用灵气/突破效果。
5. 循环类首尾的形状、位置、亮度与速度连续；不要把完全相同首尾帧同时停留两次造成顿挫。一次性类首尾淡出至透明，不强制循环；播放器显示末帧不能跳到超出帧数的空格。
6. 除另有说明，动画只影响自己预留区域，`pointer-events:none` 不能代替“视觉上不遮按钮”的验收。减少动态效果模式可用从序列抽取的静态代表帧，无需另生成一张新图。

### 4.4 体积与性能建议

以可读性与正确透明为先，再做无损优化。建议单张 UI 图标不超过 150KB、头像不超过 500KB、插画不超过 2MB、单个特效图集不超过 4MB；超过预算需记录原因并实际测量解码与内存，不为压缩改成带色边的索引透明。RGBA 解码内存约为宽×高×4 字节，不只看磁盘大小。只在当前可见场景播放一个对应主特效，关闭弹窗后释放循环；不要同时预解码全部特效。上述数值为预算目标，不是当前已测得的运行性能结论。
