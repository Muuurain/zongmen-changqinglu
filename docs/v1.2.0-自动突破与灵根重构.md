## 1. 玩家操作与默认行为

弟子页面顶部新增“自动突破”面板：选择策略、每人丹药数量（1—3），然后点击“一键自动突破”并确认，即可执行一轮。弟子列表每行有“参与”复选框，取消后仅排除自动处理，仍可手动突破。新弟子和旧档缺失该字段的弟子默认参与；月结自动执行默认关闭，升级或读档不会直接触发一次批量突破。掌门也受个人开关控制。

可开启“每月修炼后自动执行”：玩家点击“闭关一月”时，在建筑产出和修炼之后、伤势恢复与寿元结算之前执行一轮。没有实时计时器，也没有离线收益。等丹者在后续月结达到库存条件后重试；不启用月结时，获取丹药后再次点击一键按钮即可。

| 策略 ID | 页面名称 | 执行规则 |
| --- | --- | --- |
| `direct` | 直接突破 | 不用丹药，保持原成功率与失败后果。 |
| `pills` | 自动服丹 | 每人至多使用设定数量；不足时使用现有整数颗数，无丹也尝试。 |
| `wait` | 等丹再突破 | 必须凑齐设定数量才尝试；不足时不扣丹、不清经验、不占本轮尝试。 |

丹药按弟子 ID 升序分配，不会承诺同时满足所有弟子。每人每轮最多一次，不自动寻找护法，不执行九霄雷劫。只处理已参与、修为已满且通过 `canBreakthrough` 的弟子；伤者、历练/护送/渡劫及护法中的弟子跳过，健康分宗驻守者可就地突破。待选事件、战后处置、进行中的雷劫或宗门覆灭会阻止一键执行。

**风险保持不变**：自动操作复用 `tryBreakthrough`，仍有掉境、重伤、根基受损和陨落风险；掌门陨落继续走原继位逻辑。只改操作效率，不提高成功率上限，不返还失败所用丹药。界面显示风险，按钮执行前一次确认；每月执行由玩家显式勾选授权，后续不逐人确认。

## 2. 自动突破实现位置

- `data.js / AUTO_BREAKTHROUGH`：策略名称与说明；`INITIAL_STATE.autoBreakthrough` 为 `{ monthly:false, strategy:"direct", pills:1 }`。
- `game.js / setAutoBreakthrough(settings)`：验证全局策略、布尔月结开关与 1—3 整数丹量。
- `game.js / setDiscipleAutoBreakthrough(id, enabled)`：修改指定存活弟子的布尔参与字段。
- `game.js / autoBreakthroughError()`：检查未完成流程；`runAutoBreakthrough()` 固定 ID 顺序、逐人重新验证，复用手动入口，返回 `attempted/succeeded/failed/waiting/skipped/pillsUsed/results`。此业务函数不隐式保存，由 UI 或月结负责。
- `game.js / nextMonth()`：在每月修炼后可选调用，详细结果写入本月要事；最后沿用原待选事件持久化与自动保存。
- `ui.js / renderDisciples()`：设置面板与个人开关；`updateAutoBreakthrough/setDiscipleAuto` 修改后自动存档；`confirmAutoBreakthrough` 一次确认后执行、渲染和保存，保存失败明确提示。
- `css/style.css`：沿用现有颜色变量、`rem` 与按钮风格；设置栏可换行，名录使用局部横向滚动，避免挤掉个人开关与操作。

## 3. 新灵根数据与统一名称

旧 `root: number` 改为结构化对象，所有人物生成入口统一走 `makeDisciple → rollSpiritRoot`：

```js
root: { kind: "normal", elements: ["金", "木"] }
// 或 { kind: "mutant", elements: ["雷"] }
```

五行顺序固定为金、木、水、火、土；多属性组合不重复，按此顺序存放。异灵根固定为雷/冰/风中的一种，本轮没有混合异属性与五行，也没有额外的“无属性天灵根”。名称是本游戏采用的传统修仙分类约定。

| 种类 | 示例名称 | 分类 | 基础修炼倍率 |
| --- | --- | --- | --- |
| 五行单属性 | 金天灵根、木天灵根等 | 天灵根 | 1.80 |
| 两种五行属性 | 金木双灵根 | 真灵根 | 1.35 |
| 三种五行属性 | 金木水三灵根 | 真灵根 | 1.00 |
| 四种五行属性 | 金木水火四灵根 | 伪灵根 | 0.75 |
| 五种五行属性 | 金木水火土五灵根 | 伪灵根 | 0.55 |
| 单一变异属性 | 雷异灵根、冰异灵根、风异灵根 | 异灵根 | 1.90 |

`ROOT_ELEMENTS/ROOT_MUTATIONS/ROOT_SPEEDS/ROOT_RECRUIT` 集中在 `data.js`。`validSpiritRoot` 校验结构，`spiritRootInfo` 统一返回名称、数量、分类和倍率，`cultivateSpeed` 只读取该倍率。弟子列表、详情、招募结果与招募事件日志已全部改用此入口，不再访问旧 `SPIRIT_ROOTS[d.root]`。

多属性的数量与修炼倍率严格反向变化，其余悟性、建筑、底蕴、长老、根基与道侣倍率保持原有叠乘方式。灵根不直接改变战斗倍率或突破概率。

## 4. 宗门实力与声望影响招募

`recruitmentProfile(opts)` 为招募概率的单一来源，UI 展示和实际抽签共用结果：

```text
P = sectPower()
实力分 = clamp(log10(1 + P / 100) / 3, 0, 1)
声望分 = clamp(reputation / 500, 0, 1)
q = clamp((实力分 + 声望分) / 2 + 寻访加成, 0, 1)
寻访加成：下山游历 0.12；入门试炼 0
天才事件：q = max(q, 0.85)
最终权重[i] = low[i] + (high[i] - low[i]) * q
```

| 灵根类 | 五灵根 | 四灵根 | 三灵根 | 双灵根 | 天灵根 | 异灵根 |
| --- | --- | --- | --- | --- | --- | --- |
| q=0 权重 | 38 | 30 | 20 | 9 | 2 | 1 |
| q=1 权重 | 5 | 10 | 22 | 33 | 20 | 10 |

两端权重均合计 100，中间线性插值；天灵根+异灵根总概率由 3% 增至 30%，低属性组合的总体概率同步提升。实力与声望各自可提高概率；单项达到上限后不再无限增长，仍保留低资质结果。无保底机制，单次高实力招募仍可能得到五灵根。寻访的原悟性 +15 继续保留。

先抽种类，再用有限 Fisher–Yates 洗牌取五行子集；异灵根的雷冰风等概率。不会用随机重抽去重的无限循环。普通招募、客卿、俘虏和收徒事件等统一生成入口均受当时宗门招贤分影响；天才事件保留资质分下限与原高悟性设定。已存在的弟子不会随声望变化重抽灵根。

## 5. 旧档迁移与回退边界

存档键仍为 `zm_cql_save_0..3`，不直接改玩家机器上的实际档案。`load` 在临时对象中迁移、校验，再替换当前状态；无版本号按 v1 处理，拒绝超过版本 3 的未知未来档。迁移不改变人物 ID、名字、境界、已积累经验、岗位、事件和任务进度，原有 v1.1.2 清理逻辑继续生效。

| 旧数字 root | 新结构 | 选择原因 |
| --- | --- | --- |
| 0—4：原金/木/水/火/土 | 保留原属性，并加入按五行顺序后继的两种属性，形成三灵根 | 维持原普通灵根 1.0 倍修炼；不将旧档全部普通人突然升级为 1.8 倍天灵根。 |
| 5—7：原变异雷/冰/风 | 对应的雷/冰/风异灵根 | 保留异属性身份，按新体系使用 1.9 倍；旧版是 1.35 倍。 |
| 8：原无属性天灵根 | 用弟子 ID 对 5 取模确定一个五行属性，形成对应天灵根 | 维持 1.8 倍，并补上具体属性，反复读档不会重抽。 |

缺少个人参与字段时补 `true`；已保存的 `false` 严格保留。缺少全局设置时使用默认且关闭月结；设置损坏时修正策略/丹量，同时强制关闭月结，避免错误配置引起意外的自动冒险。保存时写 `saveVersion:3`。

**注意**：新版 `root` 对象无法被旧版读取。保留升级前的手动档副本有助于回退；不要用 v1.1.2 加载已由 v1.2.0 覆盖保存的档。旧普通灵根补出的属性仅是确定性兼容选择，不代表旧档曾记录这些额外属性。当前修为保留，后续修炼按新倍率计算。
